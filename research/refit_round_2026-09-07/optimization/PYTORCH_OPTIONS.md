The initial routes were compact source-perturbation VJPs, raw CUDA graphs, and compiled backward fusion. Actual Ouro screening now favors preserving the original replicated primal and ordinary backward: on two output rows across all 191 sources, native batch-one versus batch-two gradients differed by relative Frobenius error 1.51719. The compact scalar VJP matched native batch-one exactly, while modern and legacy batched VJPs both differed from that matching scalar reference by 0.0660809. Those samples do not support adopting the batched functional route. [Measured isolation](bench_reduced.json). None of these APIs removes the 2,048 exact output directions or permits changing the 191 source locations, positions, target, or paragraph average fixed in [CONTRACT.md](CONTRACT.md).

This assessment uses the installed `torch 2.12.0.dev20260407+cu128`, git revision `6a13e444ee88996ff01cd2bab41d7f2857291646`, and primary PyTorch/NVIDIA documentation. Public `main` documentation can describe a newer build; the installed implementation controls build-specific conclusions below. This document reports CPU feasibility, not an accepted Ouro GPU engine or a throughput measurement.

| Route | Useful mechanism | Main qualification |
| --- | --- | --- |
| Modern compact VJP | One native batch-one primal; independent width-D perturbations at each source; `vmap` over the reusable pullback returns only `[directions,D]` rows per source | Needs matching-primal derivative checks and actual attention-kernel compatibility; compact requested outputs do not eliminate internal token adjoints |
| Raw CUDA graph | Capture a retained backward and its exact GPU source reduction; replay with new values in fixed-address cotangent buffers | Requires stable tensor addresses, safe stream ownership, capturable operations, and measured extra memory; replay outputs are overwritten |
| AOT/compiled backward | Fuse normalization, activation and residual operations and reduce dispatch | Disable donated buffers for repeated `retain_graph=True`; compile cost, graph breaks and numerical changes need measurement |
| Compiled Autograd | Capture a larger runtime backward graph than ordinary AOT boundaries | Installed private APIs and support differ from older documentation; a small executable test is more informative than assuming support or failure |
| Math SDPA with batching | Exposes ordinary matrix, softmax and pointwise operations to modern batching rules | Changes the attention implementation and retained activation memory; numerical equivalence and speed must be checked separately |

The existing `torch.autograd.grad(..., is_grads_batched=True)` implementation calls the legacy vmap engine. Modern `torch.func.vjp` followed by `torch.vmap` uses `FuncTorchBatched` dispatch instead. In the installed CPU dispatcher inspection, `aten::silu_backward` and `aten::_softmax_backward_data` have modern batching rules but no legacy `Batched` rule. `bmm` has both. Flash, efficient and cuDNN SDPA backward operators have neither direct batching rule in this build; successful forward batching is not evidence of a specialized backward rule. Unsupported operations may use fallbacks or fail, so runtime warnings and measurements still matter. [PyTorch autograd.grad documentation](https://docs.pytorch.org/docs/main/generated/torch.autograd.grad.html), [Jacobian transform tutorial](https://docs.pytorch.org/tutorials/intermediate/jacobians_hessians.html).

`torch.func.vjp(f, inputs)` executes `f` once and returns a reusable pullback. The installed pullback defaults `retain_graph=True`, but its `create_graph=None` default follows ambient gradient mode. The candidate explicitly passes `create_graph=False` on every call to avoid constructing higher-order graphs. Repeatedly invoking an entire `jacrev(f)` function for successive manually selected chunks could repeat the primal; retaining one VJP closure makes reuse explicit. A transform's own `jacrev(..., chunk_size=...)` is a separate supported interface, with chunk size one avoiding vmap constraints. [Installed VJP implementation](/home/moloch/ouro_project/venv/lib/python3.14/site-packages/torch/_functorch/eager_transforms.py:405), [jacrev documentation](https://docs.pytorch.org/docs/main/generated/torch.func.jacrev.html).

The implemented [reduced_vjp_candidate.py](reduced_vjp_candidate.py) preserves the native forward and attention selection. It injects each FP32 source vector as `cast(h.float() + valid_mask * delta / M)` and returns the FP32 target-position **sum**. Differentiating with respect to each independent delta produces the source-position mean. Injection hooks must return the updated block output: Ouro's existing `LoopTap` discards hook return values, so this candidate attaches directly to the same physical module and filters its `current_ut` keyword. It preserves tensor/tuple/list output layouts, removes hooks in `finally`, and never calls `ActivationRecorder.requires_grad_()` inside the functional transform. The returned context supports `rows(start, batch)`, arbitrary `apply_cotangents([B,D])`, an ordinary `apply_scalar([D])` pullback on the same primal, and explicit graph release with `close()`.

Optional diagnostic mode returns detached residuals from every virtual event and any supplied modules, such as `audit_modules={'loop_norm': model._final_norm}`, as `torch.func` auxiliary outputs. This checks zero-perturbation primals and normalized loop carries without retaining an extra differentiation graph. Disable these clones for throughput measurements. The model must already be frozen and in evaluation mode on one device. Unsupported no-grad decorators or transform-incompatible custom operators fail visibly; this candidate does not silently alter the native execution. PyTorch also documents restrictions on mutation, unsupported operations, and stateful transforms. [torch.func limitations](https://docs.pytorch.org/docs/main/func.ux_limitations.html).

The candidate's CPU-only self-test passes against the upstream fitter on linear FP32 and causal recurrent FP32/BF16 decoders, including final and penultimate targets. Every virtual residual and loop-carry normalization is bitwise equal to a native batch-one forward; scalar and modern batched pullbacks on the same primal are bitwise equal in these toy cases. Width five and chunk sizes 1, 2, 4 and 8 cover partial tails. Independent full position-by-position Jacobians across tied blocks and a carry norm pass at `atol=2e-7, rtol=1e-6` for lengths 5, 6 and 7; the largest absolute difference is `2.3841858e-7`, within the combined absolute/relative criterion. Guard, repeated/zero/random cotangent, empty-position and exception-cleanup checks pass. `torch.cuda.is_initialized()` remains false. These checks establish the toy algebra and lifecycle, not Ouro numerical parity.

Forward batch shape must be isolated from backward batching. A batch-one primal and a replicated batch-two primal can choose different floating-point kernels and yield different recurrent states. Compare native and zero-delta primals at the same batch shape first; then compare ordinary scalar and batched VJPs on that same primal. Only then compare the resulting engine against the saved replicated-primal reference. A finite result or agreement among several derivative batch sizes is insufficient evidence of fidelity.

CUDA graphs fit the repeated-cotangent workload because the primal graph, weights and intermediate storage remain fixed across direction sweeps. Capture the backward on the same explicit side stream that built the primal; backward operations follow the streams of their corresponding forward operations. Keep saved activations, cotangent buffers and output addresses alive, update values before replay, and consume or copy outputs before replay overwrites them. CPU copies, synchronization, logging and data-dependent host decisions stay outside capture. Raw capture is more suitable than blindly wrapping the entire model with `make_graphed_callables`, whose documented restrictions include hooks at wrapping time, higher-order derivatives and autocast caching. Graph memory pools and prompt-specific retained graphs must be released or reused according to their execution-order constraints. [PyTorch CUDA semantics](https://docs.pytorch.org/docs/main/notes/cuda.html), [make_graphed_callables](https://docs.pytorch.org/docs/main/generated/torch.cuda.make_graphed_callables.html), [NVIDIA PyTorch integration](https://docs.nvidia.com/dl-cuda-graph/latest/torch-cuda-graph/torch-integration.html).

For compiled retained backward, the installed `torch._functorch.config` explicitly requires `donated_buffer=False` when using `retain_graph=True`. Its default backward autocast assumption is `same_as_forward`; when forward autocast is active but backward runs outside it, the documented setting is `backward_pass_autocast='off'`. Use scoped configuration and restore it after the experiment. Ordinary AOT compilation and runtime Compiled Autograd are distinct mechanisms: neither justifies assuming that a large complete Ouro backward will compile quickly, preserve numeric behavior, or automatically hoist the primal across separately invoked transforms. Start with a representative block and a suffix crossing a loop norm, or an executable small retained-VJP graph, before spending full-model compilation time. Frozen weights already suppress weight-gradient matrix multiplications; the remaining opportunity is fusion, allocation, dispatch and attention execution. [Installed configuration](/home/moloch/ouro_project/venv/lib/python3.14/site-packages/torch/_functorch/config.py:330), [Compiled backward semantics](https://docs.pytorch.org/docs/main/user_guide/torch_compiler/torch.compiler_backward.html), [Compiled Autograd tutorial](https://docs.pytorch.org/tutorials/intermediate/compiled_autograd_tutorial.html).

Finally, math SDPA is an explicit engine choice. PyTorch documents backend-dependent numerical results and the math implementation's higher-precision intermediates for low-precision inputs. It may resolve batching bottlenecks while increasing retained memory or changing the primal. Keep the original backend for the first candidate test, and record any later switch with its own matching-primal, derivative and full-workload timing evidence. [SDPA documentation](https://docs.pytorch.org/docs/main/generated/torch.nn.functional.scaled_dot_product_attention.html).

The additional [saved_tensor_candidate.py](saved_tensor_candidate.py) keeps the original replicated batch and ordinary `autograd.grad` computation. Construct `ReplicatedSavedTensorHooks(model, batch_size=B, seq_len=T)` and enter it around the native forward only. PyTorch calls its pack hook when saving an intermediate and later calls its unpack hook during backward, even after the context exits. Unpack must reproduce the saved values; this candidate additionally restores the exact shape, dtype, device, stride and storage offset. [PyTorch saved-tensor hooks tutorial](https://docs.pytorch.org/tutorials/intermediate/autograd_saved_tensors_hooks_tutorial.html), [installed hook contract](/home/moloch/ouro_project/venv/lib/python3.14/site-packages/torch/autograd/graph.py:264).

Compression requires a recognized explicit batch axis or flattened `B*T` axis, a dense nonoverlapping layout, at least 4 KiB nominal savings by default, and **every lane's identical value bits**. A valid axis zero is preferred when dimensions are ambiguous; otherwise exactly one candidate is required. This handles B=16 matching the head count and B*T=2048 matching the hidden width. Reconstruction is identity along any selected axis when every lane is verified equal, so semantic axis ambiguity does not weaken value preservation. Integer reinterpretation catches signed-zero differences and preserves NaN payloads. Parameters and buffers, including offset/transposed aliases, are excluded by underlying storage pointer. Other ambiguous, stepped, overlapping, expanded and nonidentical tensors remain ordinary detached saved tensors. Packed payloads contain an independent cloned lane and metadata; an optional same-object/version reuse cache uses weak references only. Unpack allocates the original strided layout and broadcasts the lane into it. It has no equality checks, `.item()`, synchronization or persistent materialization cache, so pack can run before CUDA capture and unpack can be tested inside captured backward. Capture compatibility remains a GPU acceptance test.

CPU tests pass six original/transposed/flattened/offset round trips with exact value bits, strides and offsets; weak-reference checks show the original tensor/storage is released. Additional actual-size ambiguous cases `[16,16,128,128]` and `[2048,2048]` compress on axis zero, restore exact bits/layout, and reject a differing lane. Sixteen full-J comparisons across FP32/BF16, B=1/2/4/8, final/penultimate targets and tied recurrent blocks with a carry norm are bitwise equal to the original fitter. Exception cleanup and NaN/signed-zero guards pass, with CUDA uninitialized. Some FP32 toy intermediates already have nonidentical lanes and are correctly skipped. `stats()` reports pack/unpack counts, skip reasons, compressed layouts, logical payload bytes, maximum reconstruction bytes and total materialized bytes. These are not allocator savings: other aliases can retain full storage, and nonzero offsets increase reconstruction allocation. Equality costs one host decision per candidate tensor; decompression adds allocations and copies each backward. Python unpack counters advance during capture, not each graph replay. Measure memory and end-to-end throughput before adoption; preserve the no-mutation contract after packing.
