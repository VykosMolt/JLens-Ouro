# Confirmation controller protocol v1

Frozen with root on 9 September 2026. Canonical digests use UTF-8 JSON with sorted keys, separators `,` and `:`, `ensure_ascii=False`, `allow_nan=False`, and no newline. File records instead hash the actual stored bytes (including any newline). Paths below are regular files with no symlink components. All payload names are safe relative POSIX paths.

`plan` and `create` take `--run-config PATH --prior-debit PATH --job-cap-usd NUMBER` and the old bundle/balance or create/root/notice/key arguments. A job cap can only reduce the cap recorded in the immutable prior debit (initially $4). This round's total cap stays $25.

Run configuration (`schema=confirmation_run_config.v1`): `run_id` (safe identifier), `run_spec_path`, `output_contract_path`, `semantic_verifier={path,record:{bytes,sha256},callable:"validate_outputs"}`, `setup_budget_seconds`, `compute_budget_seconds`, `preservation_reserve_seconds` (at least 600), and `transfer_timeout_seconds` (positive, no greater than the preservation reserve). All paths are absolute and local. The controller hashes run spec/contract/config/verifier before planning and before creation. The requested setup+compute+preservation+600-second termination window and $0.15 billing margin must fit the incremental and combined caps. These are conservative admission bounds, not extensions of the fixed provider TTL. The verifier's interpreter is the controller interpreter.

Output contract (`schema=confirmation_output_contract.v1`): exact fields `schema`, `run_id`, `run_spec_sha256`, `files` mapping each exact result path to `{role: STRING}`, `stages` mapping safe stage IDs to sorted lists of file paths, and `required_checks` containing `loadability`, `numerical`, and any additional named checks. Stage lists may overlap to include shared metadata. Every stage list must be a nonempty subset of `files`; final acceptance requires the full file set. Input estimators already preserved outside the worker need provenance references in output data, not duplicate new fit weights.

Every manifest/index `binding` has exactly `account_id`, `lease_name`, `pod_id`, `run_id`, `run_spec_sha256`, `output_contract_sha256`, and `controller_sources`. The controller exposes this via `artifact_handoff.binding(state)` after the owned pod has been bound. `controller_sources` is the exact filename-to-file-record mapping from the local intent, not an extensible producer field. Worker configuration must carry this exact binding.

Manifest (`schema=confirmation_artifact_manifest.v1`): exact fields `schema`, `binding`, `kind` (`stage` or `final`), `stage_id` (a declared stage ID, or null for final), `outcome` (`complete`, `stopped`, or `failed`), and `files` mapping each payload path to `{bytes,sha256}`. A stage lists exactly its contract stage's paths; a complete final manifest lists exactly all contract paths. Only `complete` can become a passed acceptance receipt. A stopped/failed terminal manifest can list the committed subset and records durable completion/salvage without allowing normal deletion. A complete manifest and its files are immutable.

The worker writes payloads under `/workspace/jlens/results/`. It writes each immutable manifest at `/workspace/jlens/manifests/ID.json` and atomically updates `/workspace/jlens/artifact_index.json`: exact fields `schema=confirmation_artifact_index.v1`, `binding`, and `manifests=[{path:"manifests/ID.json",record:{bytes,sha256}}]`. Manifest paths cannot be reused for changed bytes. The index is append-only as a set of path/record pairs; it may be rewritten atomically with the same or additional references. At most one final manifest is allowed. The final manifest is published only after payload writers stop. A stage manifest is published promptly when its files close, before later paid work.

Worker status remains `/workspace/jlens/status.json` with exact `binding`, `lease_name`, `setup_complete` (boolean), and `phase` plus optional diagnostics. A validated true setup observation is durable. Missing/later false status cannot regress it. The index and terminal manifest, rather than `phase=complete` alone, establish computation completion.

The pinned local verifier exports `validate_outputs(*, root: Path, manifest: dict, contract: dict) -> dict`. `root` contains only this manifest's copied payloads and retains their contract paths. The exact returned fields are `schema=confirmation_validation.v1`, `status="passed"`, `run_id`, `manifest_sha256` (canonical manifest digest), `contract_sha256` (actual contract file hash from the manifest binding), `checked_files` (sorted exact manifest file list), `checks` (all required contract checks explicitly boolean true), and optional `details` (object). Source bytes are checked before and after import/execution. All local payload hashes are checked before loading and again before acceptance. Missing/unavailable verifier or missing/false checks fail closed. A stage validator must validate its declared subset with shared dependencies included in that stage's file list.

The receiver writes stable manifest-keyed staging and immutable accepted generations under the local lease's `handoff/`. The watcher persists progress and the returned receipt pointer in `LEASE.json`; the worker cannot set that local acceptance field. A stage receipt is preservation evidence only. Normal deletion requires a full final receipt for the exact current binding and manifest, including successful local validation and fresh accepted-payload hashes.

`terminate --authorization PATH` requires a local root-authored document with `schema=confirmation_explicit_teardown.v1`, exact `binding`, `scope` (nonempty explicit reason), and `authorized_by="root"`; it is hashed and retained before a mutation. The document is local authorization, not a worker result. Budget emergencies remain independently enforceable and record missing/preserved evidence before deletion. `sync` retries known and newly indexed stages/final manifests; `status` is read-only; `test_lifecycle.py --smoke` will execute the standalone local CPU smoke without network/provider access.
